# База данных PCHelper

## Что уже является резервной копией схемы

Миграции `db/01_schema.sql` … `db/16_user_deletion.sql` — это история
структуры базы: таблицы, ключи, связи, индексы, триггеры, представления
и ограничения. Они лежат в git и позволяют поднять структуру с нуля
по порядку номеров.

Но живая база в Supabase могла уйти вперёд миграций. Поэтому перед
рискованными изменениями лучше снимать актуальный дамп.

## Важно про Free-план

На бесплатном плане Supabase **нет ежедневных автоматических бэкапов** —
они доступны только на Pro, Team и Enterprise. Free-проект нужно
бэкапить вручную.

Данные и структура — разные вещи:

- структура нужна, чтобы восстановить таблицы и связи;
- данные нужны, чтобы вернуть заказы, пользователей и товары;
- фото в Storage в дамп базы не входят — их надо хранить отдельно.

## Строка подключения

1. Supabase Dashboard → **Connect**.
2. Выберите **Session pooler** (порт 5432) — он работает через IPv4.
3. Скопируйте URI вида:

```text
postgresql://postgres.<ref>:<пароль>@aws-0-....pooler.supabase.com:5432/postgres
```

4. Лучше **не записывать пароль в `backend/.env`**: этот файл целиком
   упаковывается в exe. Задайте переменную только в текущем терминале:

```powershell
$env:SUPABASE_DB_URL = "postgresql://postgres.<ref>:<пароль>@aws-1-eu-west-1.pooler.supabase.com:5432/postgres"
```

`backend/.env` не перезапишет уже заданную переменную окружения.
После бэкапа её можно убрать:

```powershell
Remove-Item Env:SUPABASE_DB_URL
```

Если всё же положили строку в `.env`, удалите её перед сборкой exe.
Пароль базы в git и в промпт не пишем.

## Выгрузить только структуру

```powershell
cd backend
npm run db:schema
```

Появится `db/schema_live.sql`. Это SQL без данных: таблицы, связи,
индексы, триггеры, функции и RLS. Файл можно коммитить.

## Полный бэкап с данными

```powershell
cd backend
npm run db:backup
```

Появятся два файла в `backups/`:

- `schema-<дата>.sql` — структура;
- `data-<дата>.sql` — данные.

Папка `backups/` добавлена в `.gitignore`: там email, телефоны, адреса
и другие персональные данные. Храните её вне репозитория.

## Восстановление

1. Создайте пустой проект Supabase.
2. Выполните `schema-<дата>.sql` в SQL Editor.
3. Выполните `data-<дата>.sql`.
4. Проверьте, что последовательности (`id`) не конфликтуют.
5. Отдельно восстановите фотографии в Storage, если они нужны.

Для локальной копии можно использовать `psql`:

```powershell
psql "$env:SUPABASE_DB_URL" -f backups/schema-2026-11-22.sql
psql "$env:SUPABASE_DB_URL" -f backups/data-2026-11-22.sql
```

## Как часто делать

- Перед миграцией или массовым удалением — обязательно.
- Во время активной разработки — раз в день или перед крупными изменениями.
- После стабилизации — раз в неделю.
- Схему (`db/schema_live.sql`) обновлять и коммитить после изменений структуры.
