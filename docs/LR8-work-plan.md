# ЛР8 — план работ и решения

Состояние на 17.11.2026. ЛР7 закрыта. ЛР8 и ЛР9 выполняются параллельно с курсовой 4 курса.

## Репозиторий и ветки

- Один репозиторий: `pchelper-store`.
- `develop` — без защиты, ежедневные пуши всех участников.
- `main` — защищённая, финальный PR `develop → main`.
- CI запускается на push в `main`/`develop` и на pull request.
- Все коммиты в рамках ПЧМИ делаются с флагом `--author` от исполнителя.

## Технологические решения

- **Figma не используется** — ссылки на HTML-прототипы ЛР5 через GitHub Pages.
- **Мобильное** — PWA на базе `frontend/public/mobile.html`, не React Native.
- **Electron** — в ЛР8 только в архитектуре; portable по образцу 3 курса делается в курсовой.
- **SonarQube** — этап в CI остаётся отключённым (`if: false`) с пояснением: Quality Gate проверяется на PR, а сборку блокируют ESLint, Prettier, тесты и покрытие. Codacy/Snyk не подключаем.
- **Wiki** — обновить в конце ЛР9, добавить разделы по ЛР7–ЛР9 и ИИ.

## Что уже есть от ЛР7

- REST API `/categories`, `/products`, `/products/:id`, `/prebuilt`; 96 товаров, 7 сборок.
- React-витрина и отдельная мобильная страница.
- 24 unit-теста, 87,3 % покрытия, 23 UI-проверки, 18 мобильных проверок.
- CI/CD, Docker, Render, GitHub Pages, OpenAPI (45 операций), SQL-схема с пользователями, корзинами, заказами и отзывами, MCP-сервер из ЛР4.

## Что сделать в ЛР8

1. Backend: JWT/сессии, регистрация/вход, валидация, серверная корзина и заказы.
2. MCP: подключить к Supabase, проверить через MCP Inspector или LLM-клиент, добавить чат-бот/инструкцию.
3. Веб: адаптив 320–1920, mobile-first, Grid/Flex, clamp(), доступность ≥4.5, focus-visible, Lighthouse ≥90/90/90, W3C-валидация, PWA, тёмная тема.
4. Мобильное: PWA-режим, тач-навигация, иконка.
5. Отчёт: вклад, коммиты, ссылки на прототипы и код, скриншоты на устройствах, архитектура клиента и логика API.
